MEMORY/ en tiempo real — el fantasma piensa en voz alta

El obsidian brain ya existe en el repo (`MEMORY/`): índice, constitución, decisiones, cementerio, estado, vistas por rol. Hoy solo lo leen los agentes. La capa admin lo vuelve un panel vivo — se re-indexa en cada commit y muestra el grafo, las decisiones, y lo que está VIVO vs MUERTO, junto al pulso real del motor.

Cómo se mantiene vivo

Real-time barato

Sin websockets caros al inicio: el bot ya deja caer JSON atómico; un brain-indexer convierte `MEMORY/*.md` → `brain.json` (estructura + grafo + render) en cada commit. El server extiende el patrón stdlib actual con SSE (server-sent events) para empujar cambios. Todo en el proceso no-crítico.

Roadmap · orden por palanca

Qué se construye y en qué orden

F1
Brain visualizer admin (tu petición). Extiende `cockpit_server`: `/admin` gated, `brain-indexer` (MEMORY/ → brain.json), render markdown + grafo + estado vivo. ~3 noches
F2
Auth + checkout. Stripe webhook → tabla de usuarios → tier. Gate del /vip y /admin. ~2 noches
F3
Gráfico vivo VIP. Lightweight Charts + klines OKX (WS que el bot ya tiene) + overlay de señal (entry/stop/4TP). ~3 noches
F4
Alertas multi-canal. Web-push + email + el Telegram que ya existe. Webhook para TradingView. ~2 noches

Principio rector (constitución del repo): que por la interfaz jamás se caiga la señal. Todo esto es el hijo no-crítico del launcher — si el panel muere, el motor VIP sigue intacto. El único archivo runtime que redespliega el worker es la interfaz misma, a propósito.
